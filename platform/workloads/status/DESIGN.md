# Ryuwon Status Design Notes

## Direction

`status.openai.com` 계열의 조용한 상태판을 기준으로 한다. 목적은 서비스
소개가 아니라, 공개 주소가 지금 열리는지와 최근 공개 상태 이력이
어땠는지 빠르게 보여주는 것이다.

## Structure

- 좁은 중앙 컬럼: 데스크톱에서도 내용 폭을 크게 벌리지 않는다.
- 머리말: 서비스명과 수동 새로고침만 둔다.
- 상단 알림: 현재 전체 상태를 한 문장으로 요약한다.
- System status: 서비스 행, 구성요소 수, 현재 접속 상태, 90일 상태 막대를 한 화면에 둔다.
- 날짜 막대: 각 막대는 실제 버튼이며 `data-service-id`, `data-date`, 상태,
  공개 이벤트 목록을 가진다.
- 툴팁: hover, focus, click에서 한국어 날짜와 해당 날짜의 공개 이벤트를 보여준다.

## Data Boundary

현재 구현은 정적 상태 페이지다. 브라우저에서는 오늘의 공개 주소가 열리는지만
검사한다. 과거 날짜는 별도 출처가 없으면 회색 `기록 없음`으로 둔다.
정확한 가용률이나 내부 헬스체크 결과처럼 보이는 값을 만들지 않는다. 내부
노드명, 사설 IP, 백업 위치, 복구 URL, 장애 원인은 노출하지 않는다.

실제 장기 이력 저장소가 생기면 과거 날짜 막대와 우측 요약 문구를 API 또는
정적 JSON 산출물로 교체한다. UI 계약은 그대로 유지한다.

## Responsive Rules

- 720px 이상: OpenAI Status처럼 행 내부에 도메인, 구성요소, 현재 접속 상태를 한 줄로 둔다.
- 520px 이하: 현재 접속 상태를 다음 줄로 내리고, 짧은 설명을 보이게 한다.
- 상태 막대는 모바일에서도 가로 스크롤 없이 90일 범위를 압축해서 보여준다.
- 툴팁은 뷰포트 안쪽으로 위치를 보정한다.

## QA Focus

- 날짜별 막대가 모두 접근 가능한 버튼인지 확인한다.
- `2026-06-06` n8n 막대 hover/focus에서 기록 없음 안내가 보이는지 확인한다.
- 데스크톱, 태블릿, 모바일에서 가로 넘침이 없는지 확인한다.
- 현재 접속 확인 실패 시 상단 알림과 해당 행의 최신 막대가 장애 상태로 바뀌는지 확인한다.

## Size Note

SIZE_OK: 이 status page는 빌드 파이프라인이 없는 정적 ConfigMap workload다.
현재는 `index.html`, `styles.css`, `app.js`를 그대로 마운트하는 쪽이 배포면이 가장
작다. 실제 공개 이력 데이터 소스나 번들러를 붙이는 시점에 JS/CSS를 모듈 단위로
나눈다.
